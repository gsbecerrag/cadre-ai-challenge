## Architecture decisions (each is an ADR candidate)

1. KB-in-prompt, no vector RAG (ADR-0001): knowledge/*.md in git, compiled at startup into a prompt-cached system prompt with section IDs for citations (~25K tokens). Seam `KnowledgeSource.load() -> list[Doc]`. Firestore-backed KB (admin edits without deploy) = Phase-2 upgrade; vector retrieval Phase 2 with trigger "KB > ~50 pages or non-engineer edits". Alternatives rejected: Bedrock Knowledge Base, Firestore vector search, Firecrawl ingestion.
2. OpenRouter as the sole runtime LLM provider (ADR-0002): Cadre supplied the key; OpenAI-compatible API → model switching = env var; usage.cost per request; Anthropic prompt caching passes through (cache_control, 1h TTL). Default anthropic/claude-sonnet-5 ($2/$10 per M, cache read $0.20); judge anthropic/claude-haiku-4.5; triage Sonnet 5. Benchmark set: claude-sonnet-5, claude-haiku-4.5, openai/gpt-5.6-sol, google/gemini-3.7-flash. Gotchas: temperature ignored on Sonnet 5/GPT-5.x; mid-stream errors arrive as HTTP 200 + finish_reason "error"; `models: [...]` gives one-line fallback (Phase 2). Alternatives: Anthropic direct (Phase 2 impl), Bedrock (feature gaps: no Skills/Files/web fetch), Vertex.
3. GCP lock-in with seams (ADR-0003): Cloud Run (one container: FastAPI + built React SPA), Firestore Native (nam5), Firebase Auth, Firebase Functions (Python) — tooling already logged in; Firebase preference; Cloud Run best for SSE. Seams `ModelProvider` (openrouter + stub), `ConversationStore` (firestore + memory), `KnowledgeSource` (files), `Notifier` (firestore write). Portability = tested seams with one prod impl each; untested second impls are slides, not properties. Alternatives: AWS (App Runner streaming issues, Bedrock gaps), Vercel (CLI absent, no Python).
4. Raw tool loop over an agent framework (ADR-0004): single agent, ~5 tools (capture_lead, escalate, show_walkthrough, offer_live_handover, navigate_to*), history from Firestore per turn; ~80-line loop = full feature access + "I know every line". LangGraph named Phase-2 runtime (trigger: multi-agent or durable multi-step workflow). Alternatives: PydanticAI (2nd choice), LangGraph (graph with one node; needs custom Firestore checkpointer), Google ADK (Claude behind LiteLLM shim), Bedrock AgentCore (AWS-only).
5. Event-driven triage agent (ADR-0005): thumbs-down writes `feedback/{id}` → Firebase Function `on_document_created` → one Sonnet 5 call with structured output {category: kb_gap|wrong_escalation|hallucination|tone|pii|bug|other, summary, evidence[], suggested_kb_addition?, suggested_eval_case?, severity} → `triage_reports/{feedbackId}` (idempotent) + Langfuse comment/score → Triage tab in console. Chat API never knows the triage agent exists; Firestore is the event bus; same pattern for future agents (lead enrichment, hand-over timeout). `make deploy-functions` copies core/ into functions/. Fallback if Functions blocked: FastAPI BackgroundTasks + --no-cpu-throttling. Alternatives: BackgroundTasks (CPU throttling risk), Eventarc→Cloud Run (manual protobuf decoding), Pub/Sub.
6. Two-profile PII handling (ADR-0006): user's pii-redaction skill (deterministic pass-1 Redactor with Luhn/mod-97/check-digit validation; guardrail behaviour rules) adopted; `core/pii.py` with profiles `refuse` (cards→last4, IBAN, gov IDs, credentials/OTP, sensitive → applied pre-model and pre-storage) and `full` (refuse set + emails/phones tokenized → traces, logs, notification free text). Lead typed fields (name, email, phone, company) stay raw — the product needs them. B2B refinements: business contact details welcome, company names always stay, pass-2 (model-based names/addresses) deferred to Phase 2, confidential business data isn't PII but the bot declines to need it ("a strategist will cover that under NDA"). `--manifest` counts → Langfuse tag per turn.
7. Daily.co for live video hand-over (ADR-0007): prebuilt iframe, room per handover via REST, no login for either side; Jitsi = self-hosted vision target (public meet.jit.si needs an authenticated moderator → lobby friction). Offered only when an agent is `online`; `LIVE_HANDOVER_ENABLED` flag → callback path otherwise. State machine `offered → accepted_by_user → pending_agent → agent_joined → in_call → ended | declined | no_agent_available`.
8. pytest evals over RAGAS (ADR-0008): no retrieval → RAGAS context metrics don't apply. `evals/` pytest + JSONL: 20 in-KB correctness, 20 hallucination traps (pricing, portal URL, SOC 2, headcount, competitor comparisons, prompt injection…), 10 qualification/tool. Metrics: correctness (LLM judge, paraphrase-tolerant), escalation correctness (binary), tool correctness, groundedness (claim-by-claim vs KB). Haiku judge; results to Langfuse datasets; same suite drives the model benchmark. User hand-validates the 30 trap+tool cases.
9. BANT-lite qualification in code (ADR-0009): `capture_lead` tool args are the signals (industry fit, company size/role, concrete initiative/pain, timeline/budget, explicit intent); score 0–5 computed in code; ≥3 unlocks the live-call offer, made once. Alternatives: intent-only, offer after N turns.
10. Firebase Auth on the console, anonymous prospects (ADR-0010): Google sign-in + `ADMIN_ALLOWED_EMAILS` allowlist; server verifies ID token on console/handover/triage endpoints. Fallback: shared CONSOLE_TOKEN. Never open.

Other settled points: stateless API (no in-process agent state); capacity model formula `parallel ≈ min(instances×80, provider_TPM ÷ tokens_per_turn)` (~1.2¢/turn, ~7¢ per 6-turn conversation on Sonnet 5 cached); stub-provider 200-VU smoke test if time; structured JSON logs with LOGLEVEL + session_id/request_id/langfuse_trace_id; in-console realtime notification (Firestore onSnapshot + browser Notification) instead of Slack/email; GitHub Actions on PRs (lint, unit, stub-subset evals), deploy via `make deploy`; walkthrough cards + dummy portal (mock routes /portal, /portal/tools, /portal/agents, /portal/results with "Demo portal · mock data" badge) built by a parallel subagent; in-app navigation (navigate_to tool) only if time; guardrail top risks: invented portal/login URL and hallucinated pricing → rule "state only what the KB states, cite the section, otherwise redirect"; no runtime MCPs; HubSpot = Phase-2 CRM box.
